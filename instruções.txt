Contexto atual:
O ZeroInsight já possui:
- pipeline CLI;
- UI desktop em PySide6;
- geração de posts;

Nova tarefa:
Evoluir o ZeroInsight para gerar posts e Stories de Instagram com base em um documento de comunicação visual da empresa, em formato PDF ou DOCX, e permitir que o usuário escolha qual IA usar para texto e imagem, incluindo providers conhecidos e um provider customizado com endpoint e API key.

Objetivo principal:
Adicionar uma camada de Brand Intelligence / Comunicação Visual que leia um PDF ou DOCX institucional da empresa, extraia diretrizes de marca e aplique essas diretrizes na geração de:
- roteiro/copy do post;
- prompt visual;
- imagem base;
- layout final;
- CTA;
- estilo textual;
- cores;
- restrições de linguagem;
- revisão/compliance.

Também adicionar uma camada de AI Providers para permitir troca flexível entre modelos de texto, visão e imagem.

Não quebre:
- CLI existente;
- UI existente;
- geração de blog;
- geração de Stories;
- Brave/CDP;
- build Windows;

Não implemente:

- hardcode de secrets;
- dependência obrigatória de API externa para o app funcionar;
- download automático de modelos grandes;
- armazenamento inseguro desnecessário de documentos sensíveis.

Parte 1 — Leitura de PDF/DOCX de comunicação visual

Criar módulo:

zero_insight/
  brand/
    __init__.py
    document_loader.py
    brand_extractor.py
    brand_profile.py
    brand_assets.py
    brand_validator.py
    brand_prompt_builder.py
    cache.py

Funcionalidade:
1. Permitir selecionar/importar um arquivo:
   - .pdf
   - .docx

2. Extrair conteúdo textual:
   - PDF: usar PyMuPDF ou biblioteca leve equivalente.
   - DOCX: usar python-docx.
   - Não usar OCR no MVP, exceto se já houver dependência disponível. Se o PDF for imagem escaneada, avisar claramente que o documento não possui texto extraível.

3. Extrair imagens/assets quando possível:
   - logos;
   - imagens internas;
   - exemplos visuais;
   - paleta aparente, se possível.
   
   Se a extração de assets for complexa, implementar o básico:
   - salvar imagens extraídas em uma pasta da campanha/marca;
   - permitir escolher manualmente o logo na UI.

4. Gerar um BrandProfile estruturado em JSON.

Modelo mínimo:

BrandProfile:
- brand_name: str
- source_document_path: str
- created_at: str
- summary: str
- tone_of_voice: list[str]
- forbidden_terms: list[str]
- preferred_terms: list[str]
- visual_style: list[str]
- color_palette: list[dict]
  - name
  - hex
  - usage
- typography_notes: list[str]
- logo_usage_notes: list[str]
- layout_rules: list[str]
- image_style_rules: list[str]
- content_rules: list[str]
- compliance_rules: list[str]
- target_audience: list[str]
- cta_style: list[str]
- examples: list[dict]
- raw_extracted_text_excerpt: str

5. Criar fallback determinístico:
Se nenhuma IA estiver configurada, o sistema deve conseguir gerar um BrandProfile básico a partir de heurísticas:
- detectar nome da marca por título/cabeçalho se possível;
- detectar cores hex no texto;
- detectar termos recorrentes;
- detectar se o documento fala de tom, logo, paleta, tipografia, uso incorreto, etc.;
- gerar profile parcial com status "needs_review".

6. Criar extração via IA opcional:
Se houver provider de texto configurado, enviar o conteúdo extraído para IA e pedir um BrandProfile estruturado.
A resposta deve ser validada antes de salvar.
Se a IA retornar JSON inválido, tentar corrigir uma vez; se falhar, salvar erro legível.

7. Salvar perfis em:

%APPDATA%/ZeroInsight/brands/
ou diretório equivalente do projeto em modo dev.

Exemplo de saída:
brands/
  requisite/
    brand_profile.json
    source/
      manual_comunicacao_visual.pdf
    assets/
      logo_01.png
      extracted_image_01.png

Interfaces mínimas:

TextProvider:
- name: str
- generate_text(prompt: str, system_prompt: str | None = None, temperature: float = 0.4) -> str
- generate_json(prompt: str, schema_hint: dict | None = None) -> dict

ImageProvider:
- name: str
- generate_image(prompt: str, width: int, height: int, output_path: Path, negative_prompt: str | None = None) -> Path

VisionProvider:
- name: str
- analyze_image(image_path: Path, prompt: str) -> str

ProviderConfig:
- provider_type: "text" | "image" | "vision"
- provider_name: str
- model: str
- api_key_env: str | None
- api_key_value: str | None
- base_url: str | None
- endpoint: str | None
- extra_headers: dict
- extra_params: dict

Providers obrigatórios no MVP:
1. MockTextProvider
2. MockImageProvider
3. MockVisionProvider
4. CustomTextProvider
5. CustomImageProvider
6. CustomVisionProvider

Providers conhecidos:
Criar adapters preparados para:
- OpenAI
- Anthropic
- Gemini
- Groq
- Replicate
- Stability

Mas não obrigar todos a funcionar se SDK não estiver instalado.
Regra:
- Preferir chamadas HTTP com requests/httpx quando simples.
- Evitar dependência obrigatória de vários SDKs.
- Se um provider conhecido não tiver dependência/configuração, retornar erro amigável:
  "Provider configurado, mas credenciais ou dependências não foram encontradas."

Provider custom:
O usuário deve conseguir informar:
- nome do provider;
- tipo: texto, imagem ou visão;
- endpoint/base URL;
- API key;
- modelo;
- método HTTP, default POST;
- headers extras;
- formato de payload;
- mapeamento da resposta.

Para simplificar o MVP:
Implementar custom provider em modo OpenAI-compatible primeiro.

CustomTextProvider:
- endpoint/base_url
- api_key
- model
- usar formato compatível com:
  POST /chat/completions
  messages: system/user
  model
  temperature

CustomImageProvider:
- endpoint/base_url
- api_key
- model
- prompt
- width
- height
- Deve suportar dois modos de resposta:
  1. URL de imagem
  2. base64 de imagem

CustomVisionProvider:
- endpoint/base_url
- api_key
- model
- prompt + imagem em base64
- resposta textual

Na UI, deixar claro:
"Custom provider usa formato OpenAI-compatible no MVP."

Parte 7 — Prompt builder

Criar BrandPromptBuilder com prompts internos.

Prompt para extrair BrandProfile de documento:

Sistema:
Você é um especialista em branding, comunicação visual e social media. Extraia diretrizes objetivas de comunicação visual a partir do documento fornecido. Responda apenas JSON válido.

Usuário:
Abaixo está o texto extraído de um manual/documento de comunicação visual. Gere um BrandProfile com campos:
brand_name, summary, tone_of_voice, forbidden_terms, preferred_terms, visual_style, color_palette, typography_notes, logo_usage_notes, layout_rules, image_style_rules, content_rules, compliance_rules, target_audience, cta_style, examples.

Regras:
- Não invente informações ausentes.
- Se algo não estiver explícito, use lista vazia ou marque como "não identificado".
- Se encontrar cores hex, preserve.
- Se encontrar nomes de fontes, preserve.
- Se houver regras de uso incorreto, coloque em forbidden_terms ou layout_rules.
- Se houver exemplos de linguagem, preserve de forma resumida.
- Responda apenas JSON.

Prompt para gerar copy de Story com BrandProfile:

Sistema:
Você é um copywriter de social media especializado em comunicação institucional, jurídica e financeira. Gere textos curtos, claros e seguros para Instagram Stories, respeitando o BrandProfile.

Usuário:
Tema:
{topic}

Objetivo:
{objective}

Público:
{audience}

CTA:
{cta}

BrandProfile:
{brand_profile_json}

Gere {slides} stories em JSON.
Cada story deve ter:
order, hook, body, cta, visual_idea, image_prompt, compliance_notes.

Regras:
- Não use termos proibidos.
- Não prometa resultado garantido.
- Não use linguagem sensacionalista.
- Não invente dados jurídicos.
- Texto do Story deve ser curto.
- CTA deve ser claro.
- O image_prompt deve orientar apenas imagem/fundo/ilustração, sem texto embutido.
- Responda apenas JSON.

Prompt para imagem:

Gerar imagem base para Instagram Story 9:16.
A imagem será usada como fundo/visual principal, sem texto embutido.
Estilo da marca:
{visual_style}
Cores preferenciais:
{color_palette}
Tema:
{topic}
Ideia visual:
{visual_idea}
Regras:
- Não inserir texto.
- Não inserir logotipo fictício.
- Não inserir marcas falsas.
- Evitar elementos poluídos.
- Composição limpa com espaço livre para texto.
- Visual institucional, confiável e moderno.
